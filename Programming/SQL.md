# TIPS

- U CAN USE THIS FOR AUTOINCREMENT 
```
CREATE TABLE USERS( ID INT(10) PRIMARY KEY AUTO_INCREMENT, EMAIL CHAR(12));
```
- U CAN FORCE SAYING TO ADD VALUE BY SAYING 
```
CREATE TABLE USERS( ID INT(10) PRIMARY KEY AUTO_INCREMENT, EMAIL CHAR(12) NOT NULL);
```
- U CAN FORCE THEM SAYING SHOULD BE UNIQUE BY 
```
CREATE TABLE USERS(
	ID INT(10) PRIMARY KEY AUTO_INCREMENT, 
	EMAIL CHAR(12) NOT NULL UNIQUE );
```
- FOR STRING VALUE WITH UNSPECIFIED SIZE 
```
CREATE TABLE USERS(
	ID INT(10) PRIMARY KEY AUTO_INCREMENT, 
	EMAIL CHAR(12) NOT NULL UNIQUE 
	BIO TEXT );
```
- IN SHORT 
```
UNIQUE          FOR FORCING UNIQUENESS
AUTO_INCREMENT  AUTOMATICALLY INCREMENTS VALUE
NOT NULL        FORCING NO NULL VALUES
```

## QUERY TIPS

- USE 'LIMIT' FOR CERTAIN AMOUNT OF ROWS.
```
SELECT EMAIL FROM Users LIMIT 2;     (SHOWS ONLY TWO ROWS)
```

- MAKE IT ASCENDING OR DESCENDING
```
SELECT EMAIL FROM Users ORDER BY ID ASC LIMIT 2;
SELECT EMAIL FROM Users ORDER BY ID DESC LIMIT 2;        NOTE 'ID' IS COLUMN NAME
```

## KEYS

### SUPER KEY  
- COMBINE MANY COLUMNS AS A KEY.
- CAN USED TO DERIVE OTHER KEYS.
- ATRIBUTES CAN HAVE NULL VALUES TOO.
-            EX: (ID), (PHONE NUMBER) , (EMAIL)
- UNIQUE AND (NULL OR NOT NULL)
- BUT NOT UNIQUE ATTRIBUTES CAN ALSO BE USED BUT WE NEED ANOTHER UNIQUE ATTRIBUTE
-           EX: (ID,NAME)
- AND CAN ALSO USE TWO UNIQUE ATTRIBUTES TO 
-           EX: (ID ,PHONE NUMBER)
### CANDIDATE KEY
- MINIMAL SUPER KEY
- ARE SEPERATE OR TOGETHER BUT SHOUDN'T BE CONSIDERED AS CANDIDATE ALREADY TO PAIR IT UP.
-             EX: TAKE THE SUPER KEYS:
```
(ID), (PHONE NUMBER) , (EMAIL) ,  (ID,NAME), (ID ,PHONE NUMBER)

THE ABOVE ARE SUPER KEY

NOW REMEMBER 
*ARE NOT ALREADY CALLEN AS CANDIADTE KEY SEPERATELY OR TOGETHER 
*CAN BE ANYTHING

(ID), (PHONE NUMBER, EMAIL) (NAME)
NOW IF I GAVE THE ABOVE AS CANDIDATE KEY 
I CAN'T ADD ANOTHER CANDIDATE KEY AS 
(ID,PHONE NUMBER) OR (ID, EMAIL) OR (ID, NAME) OR (NAME , EMAIL) OR (ID , PHONE NUMBER)
CUZ IT IS ALREADY DONE MENTIONED AS A CANDIDATE KEY TOGETHER AND ALONE.
```
### PRIMARY KEY
- SHOULD BE UNIQUE AND NO NULL VALUES AND DERIVED FROM CANDIDATE KEY.
- CAN'T BE CHANGED AND VERY RARELY CHANGED
```
(ID), (PHONE NUMBER, EMAIL) (NAME)      CANDIDATE KEYS 

UNIQUE AND NO NULL

(ID)                                CAN BE CUZ NO NULL VALUE AND UNIQUE
(PHONE NUMBER) (NAME) (EMAIL)       CAN'T BE CUZ THEY CAN BE NULL BUT ALSO IT IS UNIQUE

BUT ONLY ONE CAN BE CHOSEN AS A PRIMARY KEY:
I'VE CHOSEN (ID)

syntax

	id INT AUTO_INCREMENT,
	STREET VARCHAR(255),
	OWNER_ID INT NOT NULL,

);


OR CAN BE DONE AS

  ```

### ALTERNATE KEY
- OTHER THAN PRIMARY KEYS ARE ALTERNATE KEYS. 
- ALTERNATE KEYS = CANDIDATE - PRIMARY
```
(ID), (PHONE NUMBER, EMAIL) (NAME)      CANDIDATE KEYS
(ID)                                    PRIMARY KEY

(PHONE NUMBER) (NAME,EMAIL)             ALTERNATE KEY
```

### UNIQUE KEY
- CONTAIN UNQUE VALUE AND NULL VALUE
```
UNIQUE AND NULL

```
### COMPOSITE KEY
- MORE THAN ONE ATTRIBUTE IS A COMPOSITE KEY.
- CAN BE ANY TYPE UNIQUE,ALRERNATE,CANDIDATE...

# QUERY WITH JOIN???

## JOIN

- IT IS USED TO QUERY B/W TWO DIFFERENT TABLES AT THE SAME TIME.
### TYPES OF JOIN 
- INNER
	- IT IS THE WAY TO QUERY B/W TWO TABLES TOGETHER BUT WITH SOMETHING THEY HAVE IN COMMON B/W BOTH TABLES
- OUTER
	- IT IS THE WAY TO QUERY WITH TWO TABLES TOGETHER BUT INCLUDES COMMON THINGS B/W THEM AND UNCOMMON THINGS
- RIGHT
	- CONSIST OF COMMON THINGS B/W THE TWO TABLE AND THE SECOND TABLE THAT YOU GIVE IN THE JOIN STATEMENT FOR QUERY BUT THE SECOND TABLE CONSIST OF UNCOMMON THINGS AND THE LEFT SIDE (OR THE FIRST TABLE GIVEN )'S UNCOMMON THINGS AREN'T SHOWN IN THIS.
- LEFT
	- IT IS THE OPPOSITE OF RIGHT ALL THE COMMON THINGS B/W LEFT AND RIGHT TABLE AND ALSO THE UNCOMMON THINGS OF THE FIRST TABLE SPECIFIED IN THE JOIN STATEMENT

  LETS LOOK AT A EXAMPLE
```
  CUSTOMERS TABLE
   
  CUSTOMER_ID      NAME        CITY 
      1            ALICE       NEW YORK
      2            BOB         CHICAGO
      3            CHARLIE     FLORIDA

   ORDERS TABLE

   CUSTOMER_ID     ORDER_ID     AMOUNT
       1             101         500
       2             102         700
```

### INNER JOIN
```
SELECT CUSTOMER.NAME, ORDERS.AMOUNT
FROM CUSTOMERS
INNER JOIN ORDERS
ON CUSTOMERS.CUSTOMER_ID = ORDERS.CUSTOMERS_ID;

RESULT
NAME      AMOUNT
ALICE       500
BOB         700

MEANING:    SELECT NAME AND AMOUNT AND SHOW ONLY CUSTOMERS WITH ORDER 
```

### LEFT JOIN
```
SELECT CUSTOMERS.NAME,ORDERS.AMOUNT
FROM CUSTOMERS
LEFT JOIN ORDERS
ON CUSTOMERS.CUSTOMER_ID = ORDERS.CUSTOMERS_ID;

RESULT
NAME       AMOUNT
ALICE       500
BOB         700
CHARLIE     NULL


MEANING: SHOW ALL CUSTOMERS IF NO ORDER BY CUSTOMER PLACE NULL
```
### RIGHT JOIN
```
SELECT CUSTOMERS.NAME, ORDERS.AMOUNT
FROM CUSTOMERS
RIGHT JOIN ORDERS
ON CUSTOMERS.CUSTOMER_ID = ORDERS.CUSTOMERS_ID;

RESULT
ALICE     500
BOB       700

MEANING: SHOW ALL ORDERS IF ORDER DOESN'T MATCH NAME THEN IT IS NULL.
```

> NOTE: YOU CAN USE LEFT INSTEAD OF RIGHT BY CHANGING THE\
>        FROM 'COLUMN1' RIGHT JOIN 'COLUMN2'   
>                 TO 
>        FROM 'COLUMN2' LEFT JOIN 'COLUMN1'
